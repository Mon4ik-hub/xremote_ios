# Промт: приложение для iPhone «AnimeGO Cast» с Share Extension

## Задача

Сделай приложение для iPhone с Share Extension, которое отправляет серию аниме с сайта animego.me в приложение AniLabX на телевизоре (его протокол называется XRemote).

Сценарий пользователя:

1. В Safari открыта страница тайтла `https://animego.me/anime/…`. Он нажимает «Поделиться» и выбирает наше расширение.
2. Расширение показывает название тайтла, плеер (CVH или Kodik), озвучку, качество и список серий.
3. Пользователь нажимает на серию и выбирает телевизор, на который отправить (если профилей несколько; при одном отправка сразу). Расширение находит прямую ссылку на видео и отправляет её на AniLabX. На экране — одна строка результата: «Запущено на «Телевизор»: эпизод 5, 1080p» либо причина ошибки.

Ничего не скачивается: на AniLabX уходит только ссылка, он качает её сам.

## Среда и границы

- Код пишется на Windows, macOS для локальной сборки нет. Swift, цель — iOS 17 и новее.
- Проект генерируй через XcodeGen из `ios-app/project.yml`, а не собирай `.xcodeproj` руками. Сборка и тесты — в GitHub Actions на раннере macOS (см. «Сборка через GitHub Actions»); локальной сборки нет.
- Без сторонних библиотек: только `URLSession` и `Network.framework`.
- Без App Groups, iCloud, push и прочего, чего может не быть у бесплатного Apple ID. Подпись — не в CI: CI собирает неподписанный IPA, а подписывает и ставит на телефон Sideloadly на Windows с Apple ID пользователя.
- Новые файлы — только в папке `ios-app/` и `.github/workflows/`. Папку `chrome-extension/` не менять: это рабочее расширение. Папку `ios-userscript/` не читать и не трогать: это закрытый прошлый вариант.
- Интерфейс и сообщения — по-русски. Ошибка всегда показывается на экране понятным текстом.
- Репозиторий на GitHub заводит пользователь (папка пока не git-репозиторий): без явной просьбы не делай `git init`, коммиты и push. Публичный репозиторий предпочтительнее — минуты macOS-раннеров для приватных репозиторий расходятся с десятикратным коэффициентом.

## Сборка через GitHub Actions и установка через Sideloadly

- Сдай `.github/workflows/ios.yml`: раннер `macos-15`; шаги — `brew install xcodegen`, `xcodegen generate`, затем `xcodebuild test` на симуляторе iPhone (схема с тестами), затем сборка неподписанного IPA: `xcodebuild archive -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO CODE_SIGN_IDENTITY=""`; из `.xcarchive` собери `Payload/` с `.app` и упакуй в `AnimeGOCast-unsigned.ipa`. Артефакты прогона — IPA и вывод тестов. Если шаг exportArchive без подписи не работает, собирай IPA из `.app` архива вручную — не добавляй сертификаты и secret'ы.
- Установка на телефон — на Windows через [Sideloadly](https://sideloadly.io/): он подписывает IPA Apple ID пользователя и ставит его вместе с расширением. Драйверы даёт iTunes, установленный с сайта Apple (версия из Microsoft Store не подходит) — у пользователя он уже ставится.
- Локально собрать Swift нечем: итерируй по результатам CI. Если `gh` авторизован — `gh run watch` и `gh run download`; иначе давай пользователю прямую ссылку на страницу Actions. Каждый пуш должен оставлять сборку зелёной.

## Как устроено приложение

**Контейнерное приложение** — один экран-инструкция: как включить расширение в меню «Поделиться» и что проверить, если телевизор не отвечает.

**Share Extension** — здесь вся логика.

- Активируется, если среди переданных объектов есть URL. Если это не страница тайтла на animego.me, показывает «Это не страница аниме на animego.me».
- Телевизоры задаются профилями: имя, IP и порт. По умолчанию один профиль «Телевизор», `192.168.1.140:31337`. Профили хранятся JSON-массивом в `UserDefaults` самого расширения и создаются, редактируются и удаляются там же (без App Groups контейнерному приложению они не нужны — оно только инструкция); автопоиска сервера нет.
- Телевизор выбирается в момент отправки: пользователь нажимает на серию — при нескольких профилях появляется список телевизоров (имя и адрес, последний использованный первым); нажатие на телевизор сразу отправляет серию на него и запоминает его первым в списке. Если профиль один, отправка идёт сразу, без вопроса.
- Кнопка «Профили»: экран со списком, добавлением и редактированием (имя, IP, порт, кнопка «Проверить» — `PING` именно этому телевизору, ответ показывается тут же). При удалении последнего использованного профиля «последним использованным» становится другой; у единственного профиля удаление не показывать.
- После отправки серии — кнопка «Готово», она завершает расширение.
- В `Info.plist` и приложения, и расширения добавь `NSLocalNetworkUsageDescription`: при первом подключении iOS спросит разрешение на локальную сеть.
- UI на SwiftUI, хост — `UIViewController` с `UIHostingController` в `UINavigationController`.
- Общий код (`Core/`) подключается к обоим таргетам одной папкой, без фреймворка.

Предлагаемая структура:

```
ios-app/
  project.yml
  App/                     контейнерное приложение
  ShareExtension/          Info.plist, точка входа, экраны (SwiftUI)
  Core/                    сеть animego, CVH, Kodik, XRemote, профили телевизоров
  Tests/
  README.md
```

## Что перенести

Эталон — рабочие функции расширения Chrome. Перенеси их на Swift с тем же поведением:

- `chrome-extension/background.js`: `fetchAnimeMeta`, `fetchEpisodes`, `fetchProviders`, `pickMp4`, а из `downloadEpisode` — часть до получения ссылки.
- `chrome-extension/extractors.js`: `cvhExtract` с вспомогательными, `kodikExtract`, `decodeKodikUrl`, `unescapeHtml`.

Цепочка вкратце:

1. Страница тайтла: из атрибута `data-anime-player-loader-url-value="/player/{id}"` берётся id, название — из `<h1>`.
2. `GET https://animego.me/player/{id}/episodes?page=N` с заголовками `X-Requested-With: XMLHttpRequest` и `Accept: application/json`. В ответе HTML с атрибутами серии (`data-episode-number`, …, `data-episode`), страницы перебираются до пустой.
3. `GET https://animego.me/player/videos/{episodeId}` — embed-ссылки плееров с озвучками (`data-provider-title` равен `CVH` или `Kodik`).
4. CVH: embed-ссылка → `playlist` → `video` на `plapi.cdnvideohub.com` → прямые mp4 (до 1080p).
5. Kodik: страница плеера → адрес эндпоинта из бандла → POST с одноразовыми подписями → base64 с шифром Цезаря → прямые mp4 (до 720p).

Тайтл для проверок: `https://animego.me/anime/tainaya-bitva-za-prestol-sil-neishego-printsa-duraleya-3592` (12 серий, есть CVH и Kodik).

## Подводные камни — всё проверено на настоящем AniLabX 24.11.2026

1. **XRemote — «голый» TCP.** Одна команда — одно соединение: отправляется строка JSON + `\n`, читается одна строка JSON в ответ, соединение закрывает клиент (сервер его не закрывает). Таймаут 5 секунд обязателен: на неизвестную команду сервер вообще не отвечает. Запросы строго по очереди.
2. **Поле `PLAY_DATA.SEASON` обязательно. Без него сервер AniLabX падает**, и его приходится перезапускать на телевизоре. То же относится к `TRANSLATION`, `EPISODE`, `CONTENT_TITLE`, `CONTENT_ID`: непустые строки. Для CVH сезон берётся из плейлиста, для Kodik он неизвестен — отправляй `«1 сезон»`.
3. Обязательны `PLAY_DATA.LINK_ITEM.LINK_PARTS[0]` и непустой `PLAY_DATA.PARSE_LINK`, иначе сервер отвечает `COMMAND_FAIL`.
4. **CDN CVH отдаёт файл только тому типу клиента, что запросил ссылку.** Тип записан в параметре `srcAg` ссылки, а плеер AniLabX ходит как Chrome. Поэтому запросы к `plapi.cdnvideohub.com` отправляй с `User-Agent` настольного Chrome — ссылка получится с `srcAg=CHROME`. Если `srcAg` вдруг не `CHROME`, положи в `HEADERS_FOR_DIRECT` тот же `User-Agent`: AniLabX выполняет эту просьбу.
5. **Ссылку CVH нельзя запрашивать заранее** (ни HEAD, ни GET): она рассчитана примерно на четыре обращения, после чего CDN отвечает 400. Получил — сразу отправил на AniLabX.
6. Ссылки короткоживущие: ищи ссылку только после нажатия на серию.
7. `COMMAND_SUCCESS` не означает, что видео уже идёт: CVH стартует за пару секунд, Kodik — за 5–8.
8. Запросы к animego тоже отправляй с `User-Agent` браузера.

## Формат сообщения

`PLAY_VIDEO` (именно такое сообщение играло на настоящем сервере):

```json
{
  "API_VERSION": 10,
  "CLIENT_NAME": "iPhone",
  "CLIENT_APP_NAME": "AnimeGO Cast",
  "CLIENT_APP_VERSION": "1.0",
  "CLIENT_TYPE": "PHONE",
  "COMMAND": "PLAY_VIDEO",
  "PLAY_COMMAND": "NONE",
  "PLAY_DATA": {
    "SERVICE_ID": 0,
    "CONTENT_ID": "animego/<id серии>",
    "CONTENT_TITLE": "<название тайтла>",
    "CONTENT_SUBTITLE": "аниме",
    "SEASON": "<номер> сезон",
    "TRANSLATION": "<озвучка>",
    "EPISODE": "<номер> серия",
    "LINK_ITEM": {
      "NAME": "<качество>p",
      "LINK_PARTS": ["<прямая ссылка mp4>"],
      "IS_ALTERNATIVE": false
    },
    "PARSE_LINK": {
      "ORIGINAL": "<embed-ссылка плеера>",
      "DIRECT": "<прямая ссылка mp4>",
      "HEADERS_FOR_DIRECT": { "Referer": "https://animego.org/" }
    },
    "RESPECT_TRANSLATION_NAME": true,
    "POSITION": 0,
    "WINDOW": 0
  }
}
```

Остальные команды — те же поля верхнего уровня (`API_VERSION` и блок `CLIENT_*`) плюс `COMMAND`:

- `PING` → `{"API_VERSION":10,"RESPONSE":"ALIVE"}`
- `GET_PLAY_INFO` → `PLAYER_NOT_RUNNING` либо `COMMAND_SUCCESS` с блоком `PLAY_NFO`
- `CLOSE_PLAYER` → `COMMAND_SUCCESS`

Другие ответы: `COMMAND_FAIL`, `VERSION_INCOMPATIBLE`, `EXCEPTION`. Каждый переведи в понятную русскую фразу.

## Тесты

XCTest — запускаются в CI на симуляторе iPhone, без сети, с заготовками:

- разбор страницы тайтла, списка серий и списка плееров по фрагментам HTML;
- раскодирование ссылок Kodik (Цезарь + base64);
- выбор потока по качеству;
- сборка сообщения: обязательные поля непустые, `LINK_PARTS[0]` равен ссылке, `PARSE_LINK` на месте, JSON заканчивается `\n`;
- клиент XRemote против mock-сервера в том же процессе (`NWListener` на `127.0.0.1`): обычный ответ, молчание сервера (таймаут), запросы по очереди;
- хранилище профилей: сохранение и чтение, валидация адреса, «последний использованный» всплывает первым и корректно меняется после отправки, удаление (в том числе последнего использованного).

Логику на Windows можно и нужно проверять без Swift:

- `node test_extractors.mjs` из корня проекта прогоняет ту же веб-цепочку по настоящим animego/CVH/Kodik — прогоняй при переносе регулярки, чтобы Swift-код соответствовал живому сайту;
- XRemote-клиент проверяется с Windows маленьким Node-скриптом к настоящему серверу `192.168.1.140:31337` — только с разрешения пользователя и по правилам:

- Перед `PLAY_VIDEO` отправь `GET_PLAY_INFO`. Если ответ не `PLAYER_NOT_RUNNING` — ничего не запускай, идёт просмотр.
- Никогда не отправляй `PLAY_VIDEO` с пустым или отсутствующим `SEASON`: сервер упадёт.
- Ссылку CVH не запрашивай перед отправкой.
- Не больше двух тестовых запусков, после каждого — `CLOSE_PLAYER`, если плеер запустил ты.

## Serena — использовать обязательно

Работай с кодом через инструменты Serena MCP, а не чтением файлов целиком.

1. Вызови `initial_instructions`, затем `activate_project` с путём к корню проекта. Если проект не онборжен — пройди `onboarding` и сохрани память через `write_memory`: команды сборки и тестов, структура папок. В `ignored_paths` проекта добавь `downloads/` и каталоги сборки.
2. Эталон читай по символам: `get_symbols_overview` по `chrome-extension/extractors.js` и `chrome-extension/background.js`, затем `find_symbol` с `include_body=true` только для нужных функций.
3. Заведи в памяти Serena (`write_memory`) таблицу «функция JS → функция Swift», дополняй её по мере переноса — ничего не должно потеряться.
4. С первым же созданным Swift-файлом проверь `get_symbols_overview`. Если установленная версия Serena не разбирает Swift, не трать на это время: создавай и правь файлы через `create_text_file`, `read_file`, `replace_content`, `search_for_pattern`, а правильность проверяй сборкой. Если разбирает:
   - целый символ — `replace_symbol_body`;
   - новый символ — `insert_after_symbol` или `insert_before_symbol`;
   - точечная правка — `replace_content`;
   - переименование — сначала `find_referencing_symbols`, затем `rename_symbol`;
   - после правок — `get_diagnostics_for_file`.
5. Независимые вызовы Serena отправляй пакетом в одном сообщении.
